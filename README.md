# FaceTec 3D Liveness — Expo 56 Sample App

This React Native sample demonstrates FaceTec 3D Liveness in an Expo SDK 56
application. Its primary purpose is to show how a native third-party iOS SDK can
be wrapped in a local Expo module and consumed by the application like any
other package.

The sample initializes FaceTec, opens its 3D Liveness interface, relays session
requests to the configured FaceTec server, and reports the liveness result.

## How the Expo module is connected

The local module lives at [`modules/facetec-sdk`](modules/facetec-sdk). The
application declares it in `package.json`:

```json
{
  "dependencies": {
    "facetec-sdk-module": "file:./modules/facetec-sdk"
  }
}
```

Expo Autolinking discovers the module, CocoaPods reads
`modules/facetec-sdk/facetec-sdk-module.podspec`, and the podspec embeds the
FaceTec XCFramework in the generated iOS project. The module exposes the native
Swift implementation to TypeScript through the Expo Modules API.

The `ios` and `android` application directories are generated by Expo Prebuild
and are not intended to be the source of truth.

## Prerequisites

For iOS development, install:

- macOS and a compatible version of Xcode
- Node.js 24.18 or newer
- npm 10.9.4 or newer, but earlier than npm 12
- CocoaPods and the Xcode command-line tools
- An Expo account for EAS Build
- An Apple Developer account and development team
- A FaceTec developer account, device key identifier, and SDK download

> You need to sign up as a Developer with FaceTec first. Then you can download the SDK.

Download the FaceTec SDKs from [dev.facetec.com](https://dev.facetec.com/).
The SDK binaries are licensed separately by FaceTec and are intentionally not
stored in this repository.

## Install the FaceTec SDK

This version of the module expects FaceTec SDK 10.1.9 at the following paths:

```text
modules/facetec-sdk/ios/FaceTecSDK-ios-10.1.9/
modules/facetec-sdk/android/FaceTecSDK-android-10.1.9/
```

For iOS, the resulting framework must exist at:

```text
modules/facetec-sdk/ios/FaceTecSDK-ios-10.1.9/FaceTecSDK.xcframework
```

If a different FaceTec release is used, update the corresponding versioned
paths in:

- `modules/facetec-sdk/facetec-sdk-module.podspec`
- `modules/facetec-sdk/android/build.gradle`

Do not rename or remove files inside the supplied SDK. In particular, FaceTec
ships required runtime content under a `cache_*` directory. Although that name
usually indicates disposable build output, the directory is part of the SDK
and must be included in the application archive.

## Configure the environment

Create a local environment file:

```sh
cp .env.example .env
```

Set the following values:

```dotenv
EXPO_PUBLIC_FACETEC_DEVICE_KEY_IDENTIFIER=your-facetec-device-key
EXPO_PUBLIC_FACETEC_SERVER_BASE_URL=https://api.facetec.com/api/v4/biometrics
IOS_DEVELOPMENT_TEAM=YOUR_APPLE_TEAM_ID
IOS_BUNDLE_IDENTIFIER=com.example.facetecsample
```

| Variable | Purpose |
| --- | --- |
| `EXPO_PUBLIC_FACETEC_DEVICE_KEY_IDENTIFIER` | Device key identifier issued through the FaceTec Developer Portal |
| `EXPO_PUBLIC_FACETEC_SERVER_BASE_URL` | FaceTec API endpoint, or the URL of a compatible server relay |
| `IOS_DEVELOPMENT_TEAM` | Apple Developer Team ID used to sign local iOS builds |
| `IOS_BUNDLE_IDENTIFIER` | A unique bundle identifier registered to the Apple team |

Variables prefixed with `EXPO_PUBLIC_` are compiled into the client application
and must not be treated as secrets. The `.env` file itself is excluded from
Git.

## Install dependencies

```sh
npm install
```

The supported tool versions are recorded in `package.json` and `.nvmrc`.

## Run on iOS

Connect an iPhone, make sure it is enabled for development in Xcode, and run:

```sh
npm run prebuild
npm run ios
```

`npm run prebuild` runs `expo prebuild --clean`. It deletes and regenerates the
native `ios` and `android` directories from `app.config.js`, the installed
packages, and the local Expo module.

Once the native application has been installed, Metro can be started
independently with:

```sh
npm start
```

The app requests camera access when FaceTec starts. Tap **Start Liveness Check**
to open the FaceTec 3D Liveness interface.

## Configure EAS

Create the local EAS configuration from the supplied template:

```sh
cp eas.example.json eas.json
npx eas login
npx eas init
```

Before running `npx eas init` in a fork, remove the sample
`expo.extra.eas.projectId` value from `app.config.js`. EAS will then link or
create a project under the signed-in Expo account and write its project ID.

In `eas.json`:

1. Replace the FaceTec device key in each build profile.
2. Confirm the FaceTec server URL.
3. Select the appropriate `development`, `preview`, or `production` profile.
4. For App Store submission, configure the Apple Team ID and App Store Connect
   API key values under `submit.production.ios`.

The App Store Connect API key is a `.p8` file downloaded from App Store Connect.
Keep it outside version control and set `ascApiKeyPath` to its local path.
`ascApiKeyId`, `ascApiKeyIssuerId`, and `appleTeamId` must match the associated
App Store Connect account.

EAS can also manage signing credentials interactively. An active Apple
Developer Program membership is required for device distribution and App Store
submission. Preview builds use internal/ad hoc distribution, so each test
device must be registered with the Apple developer team.

The real `eas.json` is excluded from Git because it can contain account-specific
configuration. `eas.example.json` is the shareable template.

## Verify the EAS archive

The FaceTec SDK is ignored by Git but explicitly included by `.easignore`.
Before a full EAS build, verify that the SDK survived project packaging:

```sh
eas build:inspect \
  --platform ios \
  --stage archive \
  --profile preview \
  --output /tmp/facetec-eas-archive \
  --force

find /tmp/facetec-eas-archive \
  -path '*FaceTecSDK.xcframework*' \
  -type f | wc -l
```

The count must be greater than zero. Also confirm that the required FaceTec
runtime directory is present:

```sh
find /tmp/facetec-eas-archive -type d -name 'cache_*'
```

If either check returns nothing, stop and correct `.easignore` before building.
Otherwise, CocoaPods may report `no such module 'FaceTecSDK'`, or the resulting
application may initialize FaceTec but crash when opening the 3D Liveness
interface.

## Build and distribute iOS

Build a local preview IPA for registered devices:

```sh
npm run eas:publish
```

The script creates an internal-distribution IPA under
`distribute/build/preview`. It can be installed on a registered device with
Expo Orbit.

Build a production IPA and open it in Apple's Transporter:

```sh
npm run eas:publish -- --profile production
```

Build and submit through EAS instead of Transporter:

```sh
npm run eas:publish -- --profile production --eas
```

Production builds require an App Store Connect application whose bundle
identifier matches `IOS_BUNDLE_IDENTIFIER`.

For direct control without the helper script:

```sh
eas build --platform ios --profile preview --local
eas build --platform ios --profile production --local
eas submit --platform ios --profile production --path /path/to/app.ipa
```

## Android

Android support is included in the module and application:

```sh
npm run prebuild
npm run android
npm run eas:build:android -- --profile preview
```

The Android FaceTec SDK folder and version in
`modules/facetec-sdk/android/build.gradle` must match the downloaded SDK.
